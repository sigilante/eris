# PROVENANCE

Eris is assembled from two upstreams. **Nothing in `third_party/` is edited in
place.** Every departure from upstream is either (a) new Eris-owned code under
`king/` or `serf/`, or (b) a patch in `patches/` applied against the pinned
submodule. This file is the authoritative ledger of *where each piece comes
from*; `CHANGES.md` is the ledger of *what we changed and why*.

If you touch a vendored file, you are doing it wrong — add an overlay or a patch
and record it here and in `CHANGES.md`.

## Upstream pins

| Submodule            | Upstream                         | Pinned commit | Ref at pin        | Role in Eris |
|----------------------|----------------------------------|---------------|-------------------|--------------|
| `third_party/vere`   | `git@github.com:urbit/vere.git`  | `81404b1a784c01ae3ecf058949dfb4529b395ef6` | `origin/develop`  | the **urth / king**: IO drivers, process supervision, newt IPC, LMDB log plumbing, the u3 noun library (`pkg/{c3,ent,ur,noun}`), and the king half of `pkg/vere` |
| `third_party/nockchain` | `git@github.com:nockchain/nockchain.git` | `73877be29bd1fafeeade1be7b95aebb0f64d8382` | `origin/master` | source of the **mars / serf** core: `crates/nockvm/rust/{nockvm,ibig,murmur3,nockvm_macros,...}` and the `Serf` kernel logic in `crates/nockapp` |

### Why these pins

- **Vere @ `origin/develop`**, not `master`: develop carries the modern serf
  architecture Eris targets — the serf owns its LMDB event log and self-replays
  (**there is no `%play` message**); snapshots are the incremental
  `image.bin`/`memory.bin`/`control.bin` scheme. The king↔serf newt contract
  (protocol **v2**) was verified byte-identical between this pin and the
  working-tree checkout the seam analysis was done on. Active 64-bit /
  pointer-compression work also lands here. Conservative alternative:
  `origin/master` (`5a7614f69bbc783736b08965fdc0a2534bb42e82`).
- **Nockchain @ `origin/master` (`73877be2`)**: same baseline as the Oct-2026
  security audit, so the serf we lift has a known security posture.

## What we take from each upstream (and what we deliberately leave)

### From `third_party/vere` — the king
- **Take:** `pkg/c3` (types), `pkg/ent` (entropy), `pkg/ur` (jam/cue bitstream),
  `pkg/noun` (the u3 noun library — the king links it for ivory-pill tracing
  and to jam/cue IPC nouns), and the **king-side** of `pkg/vere` (`king.c`,
  `pier.c`, `lord.c`, `newt.c`, drivers, `disk.c`).
- **Leave / replace:** `pkg/vere/mars.c` is Vere's own serf (the Nock computer).
  Eris does **not** run it — the Rust serf replaces that process. The spawn
  redirect needs no patch: vere's stock `--serf-bin` flag points it at
  `eris-serf` (`wrk_c`), so `mars.c` just stays compiled but unused. The only
  `patches/vere/` entry is unrelated — `0001-build-git-rev-optional.patch`, a
  build-system fix so vere builds from a submodule gitlink / tarball (no `.git`
  dir). See `docs/build.md` and `docs/seam-contract.md`.

### From `third_party/nockchain` — the serf
- **Take:** the `nockvm` interpreter + jets + PMA (`crates/nockvm/rust/nockvm`)
  and its local deps (`ibig`, `murmur3`, `nockvm_macros`, `assert_no_alloc`,
  `nockvm_crypto`); the `Serf` kernel logic from `crates/nockapp`
  (`src/kernel/form.rs`, `src/noun/ops.rs`) as the *reference* for Eris's own
  serf crate under `serf/`.
- **Isolation:** the nockvm subtree is cut out of the nockchain monorepo
  workspace by `patches/nockchain/0001-standalone-nockvm-ws.patch`, which
  installs a standalone `crates/nockvm/Cargo.toml` (generated by
  `patches/nockchain/regen-standalone-ws.py` — the reconcile-on-bump tool). The
  serf consumes nockvm by path with zero reference to nockchain's root manifest.
  Toolchain pinned in `/rust-toolchain.toml` to match. See `docs/build.md`.
- **Leave:** NockApp's king role entirely — its tokio run loop, the driver
  framework (`src/nockapp/driver.rs`, `mod.rs`), the libp2p/grpc/wallet/bridge
  crates, and all of `zkvm-jetpack` (the ~148 Nockchain-specific zk-STARK/field
  jets are irrelevant to Arvo and are **never loaded**). We do, however, read
  `zkvm-jetpack`'s `src/jets/zoon_jets.rs` as an *algorithm reference* when
  porting stdlib doors — see "Eris-owned serf jets" below.

### Eris-owned serf jets (`serf/src/jets/`)
Jets we write to cover standard-library arms nockvm leaves unjetted (because
Nockchain's kernels don't use them). Registered by `jets::eris_hot_state()` —
the stock `URBIT_HOT_STATE` followed by our entries — so nockvm's own dashboard
is **never patched**. All pinned to Hoon **k138** (`K_138`), the pill's kelvin.

- **`map.rs` — the `+by` map door** (full Vere-k138 set plus `got`/`gut`/`mar`:
  `get got gut has put del mar gas uni int dif tap key wyt apt bif run urn jab
  all any`; `rep`/`rib` deferred — gate folds Vere doesn't jet either). The
  gate-slamming arms (`run`/`urn`/`jab`/`all`/`any`) apply the sample gate via
  `nockvm::jets::util::slam`, ported from Vere's `_by_*`. *Where it comes from:*
  the core treap algorithms are cribbed from
  `zkvm-jetpack`'s `zoon_jets::h_by_*`/`h_map_*` (Nockchain's own map door), with
  the **comparator swapped** from the tip5-digest ordering (`+mor-tip`/`+gor-hip`,
  over a digest-caching node) back to the stock `mug`-based `+gor`/`+mor` from
  `nockvm::jets::sort::util`, and the node shape reverted to the stock
  `[[key value] l r]`. Cross-checked against hoon.hoon's `+by` and Vere's
  `pkg/noun/jets/.../by_*.c`. Equality is `nockvm::unifying_equality` (structural),
  not `raw_equals` — the stock `set.rs` dedup TODO is exactly that bug.
  *Why the swap is mandatory:* a stock pill's maps are `mug`-ordered treaps;
  dropping in the digest-ordered jets would build a differently-shaped tree and
  diverge from the pill's own unjetted results (corruption). Correctness is
  proven by differential tests (jet vs. a `BTreeMap` oracle + treap invariants).
- **`set.rs` — the `+in` set door** (full Vere-k138 set: `has put del gas uni
  int dif tap wyt apt bif run all any`; `rep`/`rib` deferred). Same story and
  sources as `map.rs`, cribbed from `zoon_jets::h_in_*`/`h_set_*`
  with the comparator swapped back to stock `+gor`/`+mor`; the node is the
  bare-element treap `[n l r]`. (nockvm's own `jets/set.rs` ships stock-ordered
  `jet_put`/`jet_has` but they're commented out of the dashboard, cover only two
  arms, and dedup with `raw_equals` — the bug this avoids.) Differential tests
  vs. a `BTreeSet` oracle + treap invariants.
  *Axis note:* `+by`/`+in` arms read the map/set `a` at `u3x_con_sam` (axis 30,
  via `door_map`/`door_set`), EXCEPT `wyt`, a bare trap registered at parent-axis
  3 whose `a` is at `u3x_con_2` (axis 14). Getting this wrong is silent: it only
  bites when the arm actually fires on real data (it crashed a boot). See
  `CHANGES.md` 2026-10-20 (`wyt` fix).
- **`list.rs` — chapter-`two` `+list` helpers** (`welp slag need reel skim skip
  skid murn lien sort mate`) and **`bits.rs` — atom/bit helpers** (`swp pow aor
  mat muk rub`). These are standard-library arms a stock k138 pill uses that
  nockvm's dashboard omits (Nockchain's kernels don't need them). *Where they
  come from:* ported from Vere's C jets (`pkg/noun/jets/b/{sort,reel,skid,mate,
  …}.c`, `c/{swp,pow,aor,muk}.c`, `e/{mat,rub}.c`) and hoon.hoon, in nockvm's
  house style. The gate-slamming arms apply the sample gate via `jets::util::slam`
  (= Vere's `u3j_gate_slam`); `sort` is Vere's first-pivot quicksort. `swp`
  reuses nockvm's public `bits::util::rip`/`bits::rep` so the bit-slicing is
  byte-identical to the stock jets; `pow`/`mat`/`rub` do arbitrary-precision math
  via ibig (nockvm's fork; `mat`/`rub` are tested as exact inverses); `muk` is
  murmur3 (the `murmur3` crate, == `+mug`'s hash). Registered via `LIST_JETS`;
  plain gates at `[k138 one two <arm>]`, axis 1.
- **`ob.rs` — the `+ob` `@p` obfuscator** (`fein`/`fynd`): the Feistel cipher
  that spreads adjacent planet/moon numbers across the name space. Ported from
  Vere `e/{fein,fynd}_ob.c` (murmur3 rounds over 32-bit halves). `+ob` is a child
  of `tri`: path `[k138 one two tri ob <arm>]`. Tested as inverses.
- **`po.rs` — the `+po` syllable tables** (`ind ins tod tos`): the 256-entry
  prefix/suffix syllable tables (`tos`/`ins` prefix, `tod`/`ind` suffix; `to*`
  index→syllable, `in*` syllable→`(unit index)`). Tables copied verbatim from
  Vere `c/po.c` and length-checked. `+po` is a child of `qua`: path `[k138 one
  two tri qua po <arm>]`.
- **`text.rs` — `scot`/`slaw`** (render/parse `dime`s): like Vere, jet only the
  common auras and `Punt` the rest (partial coverage is always correct). `scot`:
  `%tas %ud %ux %uv %uw`; `slaw`: `%ud %tas %p %da` — Vere's full jetted set.
  `%p` composes the `+po`/`+ob` jets to parse ship names (per Vere's
  `_parse_p`); `%da` ports the `@da` calendar (`+year`/`+yawn`/`+yule`/`+yo`/
  `+yelp`) directly in Rust, because nockvm exposes no `cook` to slam Vere's
  Hoon date helper (it has only `kick` at a known axis). Ported from Vere
  `e/{scot,slaw}.c` (+ the `u3s_etch_*`/`u3s_sift_*` in `serial.c`). Chapter
  `qua`: path `[k138 one two tri qua <arm>]`.
  All registered WITHOUT patching nockvm. Differential/round-trip tests vs. Rust
  oracles + the real boot-pill. *Per the profiling (see `docs/architecture.md`),
  these are coverage/correctness (esp. `@p`/number/path formatting), not a
  boot-speed lever.* Deferred gap buckets: `@r` floats (a SoftFloat Rust-jet
  reference exists in the `numerics` repo), crypto, and the `ut` type helpers.

## Compatibility facts that make the graft sound (verified, keep current)

These are load-bearing. If an upstream bump breaks one, it is a release blocker.

- **jam/cue** is wire-identical between nockvm and Vere/Urbit.
- **mug is byte-exact**: both use murmur3_32, seeds `0xCAFEBABE` (atom) /
  `0xDEADBEEF` (cell), same fallbacks and 31-bit fold. nockvm's 63-bit direct
  atoms vs Vere's 31-bit do **not** change the hash (it hashes little-endian
  bytes). ⇒ the `%ripe` mug and per-event replay mug-checks pass without
  `--soft-mugs`.
- **Nock 0–12** standard in both; scry (opcode 12) is an in-Nock
  `(unit (unit *))` namespace, matching Vere `.^` semantics.
- **Kelvin gap (open risk):** nockvm jets are pinned to Hoon **k138** (`K_138`
  in `jets/hot.rs`); Vere's live dashboard is **k140**. Jets only fire against a
  matching kelvin. Running current Arvo requires re-pinning the serf jets to the
  Arvo kelvin and porting missing arms (esp. the `ut` compiler jets and `e/`
  crypto). Tracked as the primary engineering cost; see `docs/architecture.md`.

## Updating a pin

1. `cd third_party/<name> && git fetch origin && git checkout <new-sha>`
2. `cd ../.. && git add third_party/<name>` to record the new pin.
3. For **nockchain**: re-run `patches/nockchain/regen-standalone-ws.py` and
   regenerate `0001-standalone-nockvm-ws.patch` (dep drift lands here). Then, for
   either submodule, re-apply the series: `patches/apply.sh <name>` (see
   `patches/README.md`). Resolve rejects; if a patch no longer applies cleanly,
   update it and note the churn in `CHANGES.md`. Bump `/rust-toolchain.toml` if
   nockchain's changed.
4. Re-verify the compatibility facts above (seam contract, mug, jam/cue, kelvin).
5. Update the pin row in this table and add a dated line to `CHANGES.md`.
